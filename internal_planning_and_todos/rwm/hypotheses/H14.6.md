# H14.6 — Low-data benchmarks gain most from cross-task deliberative ω (user hypothesis)

**Origin (user, 2026-09-01, verbatim):** "We can instead run similar runs we have rn on RememBench
and RoboCerebra. We'll need to learn the workspace tokens for those benchmarks as well. Since they
have low data across these benchmarks, I think cross task deliberation improving performance my
learning better representations and via GDN conditioning the action head for pi0.5 might be a
SIGNIFCANTLY important finding!" (replaced the venue-paired old-ω comparator P4, dropped).

**Claim (weakest form):** on ReMemBench (323 train demos) and RoboCerebra (994 episodes), a π0.5
policy post-trained with a GDN read over ω from the 4-domain deliberative encoder (28,722 segments)
beats the identical recipe with structure-free ω (ctrl-0b) and the no-ω base on the memory strata.
Stronger (not yet claimable): the gain is larger where per-benchmark data is scarcer.

**Status:** OPEN. Comparators are sealed: RoboCerebra H12 (per-domain WSM, protocol v3) = NULL on
the memory stratum — a positive there is the headline; ReMemBench per-domain ω already beats base
(dnw8 36.8, dropout-w16 38.2 vs 31.3), so the question there is whether cross-task ω adds.

**Evidence:** none yet. Priors in evidence/E-anchors.md. Encoder-level support that the
representation differs in kind: retrieval 16× vs chance (H14.1) and vision-grounding of ω (H14.11
finding: ctrl-0b ω is prompt-dominated, E1b ω is not).

**Arms (todos/T-policy-arms.md):** rcb R1 (E1b-ω) vs R2 (ctrl-0b-ω) vs base-60k curve, protocol v3
800 trials, CRN-paired, MDE₈₀ ≈ 4 pp on subtask completion; rmb P1′/P2′/P3′ vs base-60k curve,
264 rollouts, MDE 7.4 pp paired. Budgets per H14.9 (60k with milestones; rcb 48 h @400).

**Stronger variants to refuse until forced:** "gain scales inversely with data" needs ≥3 data
regimes; "GDN conditioning is the carrier" needs a non-GDN read control (not planned — parked).
